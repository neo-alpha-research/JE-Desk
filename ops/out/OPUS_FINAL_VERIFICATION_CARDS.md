## 2. 차단 결함 (반드시 수정)

**B1. 확장자와 실제 포맷이 다름 (확정)**
`main()`은 `sample_living_card_hyper_0N.png`로 저장하는데, 실제 형식은 `"JPEG"`입니다. 업로드 도구나 썸네일 생성, 다음 단계 파이프라인이 PNG로 판단해서 오작동할 수 있습니다. 확장자를 `.jpg`로 바꾸면 됩니다.

**B2. 치수 배지와 인셋 라벨에서 글자가 넘침 (확정)**
- 컷 2의 「폭 22cm 맞춤」 배지는 높이가 60px(2배 크기)인데 글꼴은 72px입니다. 1배 크기로 보면 30px 상자에 36px 글자가 들어갑니다. 글자가 배지 아래로 삐져나와 노란 화살표 선을 덮습니다.
- 컷 3의 「볼베어링 레일」 라벨도 높이 58px 상자에 72px 글꼴이라 같은 결함입니다.
- 고치는 방법: 배지 높이를 `font.size × 1.5` 정도로 늘리고, 글자는 `anchor="mm"`으로 배지 중앙에 맞춥니다.

**B3. 자간 알고리즘이 틀림 (계산상 확실)**
```python
char_w = bbox[2] - bbox[0]          # ← 잉크 폭 (사이드베어링 제외)
step = char_w + int(char_w * -0.03) # ← 자간이 글자 폭에 비례
```
- 글자 간격은 **진행 폭(advance width, `font.getlength`)** 기준이어야 합니다. 잉크 폭으로 계산하면 한글의 좌우 사이드베어링이 사라져서, 실제 자간이 −0.03em보다 훨씬 좁아집니다(대략 −8~10%em 수준으로 추정). 글자끼리 붙어 보일 위험이 있습니다.
- 공백은 잉크가 없습니다. 그래서 `"BEFORE  |  수납"`의 두 칸 공백이 거의 0px로 줄어들 수 있고, 이 부분은 Pillow 버전에 따라 다르게 나옵니다.
- 자간은 글자 폭에 비례하는 값이 아니라 **em(글꼴 크기)에 비례하는 고정값**이어야 합니다. 지금 방식이면 `6kg`이나 `|`처럼 좁은 글자와 한글의 간격이 들쭉날쭉해집니다.
- 이 폭 계산을 조건 3의 폭 검사에서도 그대로 쓰기 때문에, 폭 검사도 함께 틀립니다.

**B4. 경로 하드코딩 (확정, AGENTS.md 원칙 2 위반)**
`BRAIN_DIR` 기본값이 `C:\Users\kibae\.gemini\...`이고 원본 파일명에는 타임스탬프가 하드코딩되어 있습니다. 이대로면 골든마스터 범용 엔진에 넣을 수 없습니다. `argparse --raw1/--raw2/--raw3 --out`으로 바꾸고, 인자가 없으면 실패하도록 해야 합니다.

**B5. 사진 출처와 광고 표시 (판정 보류, 출시 전 차단)**
원본 사진은 Gemini 작업 폴더에 있고 스크립트 이름은 `hyperrealistic`입니다. **사진이 AI 생성 이미지라면** 「BEFORE」, 「규격 실측」, 「6kg 수납 완료」, 「저가형 선반 실패 후 상태」는 실제로 써본 것처럼 보이는 표시입니다. 표시광고법상 기만 표시와 추천·보증 심사지침에 걸릴 위험이 있습니다. 함께 고칠 점은 두 가지입니다.

## 3. 레이아웃 정밀 계산 (1배 크기, Pretendard 기준선 비율 약 0.95em)

- **헤드라인과 서브 사이 간격 부족:** 헤드라인 기준선은 박스 위에서 약 93px이고, 서브 글자 윗선은 약 92px입니다. **행간 여유가 0 이하라서** 받침 있는 글자가 서브 문구에 닿거나 겹칠 가능성이 높습니다. 위 여백(약 32px)과 아래 여백(약 16px)도 맞지 않습니다. 박스 높이를 160 이상으로 늘리고, `anchor="ls"`로 기준선을 직접 지정하는 방식을 권장합니다.
- **칩 오른쪽 여백:** 글자는 x=108에서 시작하는데 칩 폭은 글자 폭 + 80입니다. 그러면 오른쪽 여백이 2배 크기 기준 12px(1배로 6px)이고, 4px 테두리를 빼면 글자가 테두리에 거의 붙습니다. 왼쪽(점 포함 68px)과 비교하면 크게 비대칭입니다. 칩 폭은 글자 폭 + 108 정도로 바꾸는 것을 권장합니다.
- **보조 글꼴이 작음:** 칩 34px는 360pt 화면에서 약 11.3px, 치수 배지 36px는 약 12px입니다. 모바일 최소 가독 크기인 13px보다 작으니 40px 이상으로 올리는 것을 권장합니다.

## 4. 코드 품질

- **중복:** 3개 `render_cut_*` 함수의 약 85%가 같은 코드입니다. 이 때문에 B2 같은 버그도 컷마다 따로 고쳐야 합니다. 공통 `render_card(spec)`와 컷별 dict(칩, 점 색상, 헤드라인, 서브, 추가 요소)로 정리해야 합니다.
- **사용하지 않는 코드:** `sys`, `ImageFilter` import와 「그림자 레이어」 주석이 남아 있는데 그림자는 구현되어 있지 않습니다.
- **색 프로파일:** 스마트폰 사진은 대부분 Display P3입니다. ICC를 버리면 색이 흐리게 바뀝니다. `ImageCms`로 sRGB로 변환하는 것을 권장합니다. HEIC 파일을 쓰려면 `pillow-heif`도 필요합니다.

**올바른 자간 구현 예시:**
```python
def layout_tracked(font, text, tracking_em=-0.03):
    track = font.size * tracking_em
    xs, x = [], 0.0
    for ch in text:
        xs.append(x)
        x += font.getlength(ch) + track
    return xs, x - track  # 마지막 글자 뒤의 자간은 폭에서 제외

def draw_tracked(draw, x, baseline_y, text, font, fill, tracking_em=-0.03):
    xs, w = layout_tracked(font, text, tracking_em)
    for ch, dx in zip(text, xs):
        draw.text((x + dx, baseline_y), ch, font=font, fill=fill, anchor="ls")
    return w
```
